# OOH primer for protocol people

> Status: **stub** — outline only.

**Who this is for:** anyone working on AdCP or AAMP who needs to understand why the
OOH proposals in this repository look the way they do.

## What this document will cover

- [ ] The physical supply chain: structure → face → panel/screen → network → media owner
- [ ] The two trading worlds and why both must be supported
  - [ ] Classic/static: a panel or network reserved for a calendar period
  - [ ] DOOH: slots in a loop, sold by play, by SOV, or by modelled impressions
- [ ] The planning workflow today: brief → availability check → proposal → booking →
      copy delivery and clearance → installation or scheduling → post-campaign report
- [ ] Programmatic DOOH: how it grafted onto real-time bidding, and where the fit is poor
- [ ] Who the counterparties are: media owners, specialists/agencies, SSPs, DSPs,
      measurement bodies, landlords, municipalities
- [ ] The lead times that cannot be compressed (print, logistics, installation, clearance)
- [ ] What an agent can and cannot decide autonomously in this channel

## Open questions

- How much of the classic/static workflow is realistically in scope for an agentic
  protocol in its first generation?
- Which parts of the workflow are already standardised elsewhere (and by whom), so
  that we reference rather than redefine them?
